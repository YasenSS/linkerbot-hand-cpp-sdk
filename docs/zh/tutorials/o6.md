# O6 功能文档

O6 包含 6 个关节。SDK 默认使用原有 O6 Classic CAN 协议；如果设备刷写的是 **HOP 0.0.4** 固件，需要显式设置 `config.o6_protocol`。

本页统一使用 C++ `HandDevice` 演示常用操作。

## 使用方式

开始前先按 [准备通信接口](../connections/prepare-interface.md) 配置好编译环境和 CAN 接口。

### 先对齐三种模式

O6 的**设备端当前模式**、**主机网卡配置**和**代码里的 `o6_protocol`** 必须一致，否则 `hand.open()` 会超时报错（`device request deadline expired`）：

| 协议模式 | `config.o6_protocol` | 默认 CAN ID | Linux `can0` 配置 |
| --- | --- | --- | --- |
| Classic（旧固件默认） | `O6Protocol::kClassic`（默认） | 左手 `0x28` / 右手 `0x27` | `bitrate 1000000 fd off` |
| HOP 0.0.4 · CAN FD | `O6Protocol::kHopV004` | 请求 `0x001` / 响应 `0x401` | `bitrate 1000000 dbitrate 5000000 fd on` |
| HOP 0.0.4 · CAN 2.0 | `O6Protocol::kHopV004Can` | 请求 `0x001` / 响应 `0x401` | `bitrate 1000000 fd off` |

### 最简完整程序（Linux SocketCAN）

下面的完整示例演示连接 Classic O6 并读取 6 个关节角度（如果是 HOP 固件，按下一节改 `o6_protocol` 和 `address` 即可；Windows 替换 transport factory 即可，功能调用完全相同）：

```cpp
#include <chrono>
#include <exception>
#include <iostream>
#include <linkerbot/hand/api/device.hpp>

using namespace linkerbot::hand;
using namespace std::chrono_literals;

int main() {
    try {
        HandDeviceConfig config;
        config.model = Model::kO6;
        config.side = HandSide::kLeft;   // 按实际修改为 kLeft / kRight
        config.interface_name = "can0";

        HandDevice hand(config);
        hand.open();

        // 下文各功能片段均可直接放在此处（hand.open() 之后、hand.close() 之前）
        const auto angles = hand.get_angles(1s);
        for (const auto angle : angles.raw) {
            std::cout << angle << ' ';
        }
        std::cout << '\n';

        hand.close();
    } catch (const std::exception &e) {
        std::cerr << "Error: " << e.what() << '\n';
        return 1;
    }
    return 0;
}
```

> 提示：
> - `HandDevice` 析构函数会自动尝试关闭连接，示例使用单层 `try / catch` 即可打印出错原因。生产环境如需处理关闭失败或重试恢复，见 [API 使用指南](../guides/usage.md)。
> - 所有 `set_*` 写操作都是异步入队并返回 `CommandHandle`，需要确认发包/应答完成时调用 `cmd.wait_for(2s)` 并检查 `cmd.error()`。
> - 生产代码读取传感器前建议先检查 `sample.meta.valid`（是否有效）和 `sample.meta.stale`（是否过期）。

## HOP 0.0.4 手动接入

HOP 固件采用手动连接（不走自动扫描），需显式指定左右手、请求 ID（默认 `0x001`，响应 ID 自动为 `request_id | 0x400`）以及与设备当前帧格式匹配的 `o6_protocol`。

> `config.o6_protocol` 只决定 **SDK 用哪种帧格式收发**，不会改变灵巧手本身的模式。如需修改设备侧模式，见下一节 [切换 HOP 的 CAN 模式](#hop-can-mode)。

### 1. 配置 Linux SocketCAN 网卡

按设备当前的 CAN 模式二选一：

```bash
# 设备当前为 CAN FD（1 Mbit/s 仲裁速率 + 5 Mbit/s 数据速率，SDK 发送时关闭 BRS）
sudo ip link set can0 down
sudo ip link set can0 up type can bitrate 1000000 dbitrate 5000000 fd on

# 设备当前为 CAN 2.0（1 Mbit/s，关闭 FD）
sudo ip link set can0 down
sudo ip link set can0 up type can bitrate 1000000 fd off
```

### 2. 读取 CAN 配置与角度（完整示例）

```cpp
#include <chrono>
#include <exception>
#include <iostream>
#include <linkerbot/hand/api/device.hpp>

using namespace linkerbot::hand;
using namespace std::chrono_literals;

int main() {
    try {
        HandDeviceConfig config;
        config.model = Model::kO6;
        config.side = HandSide::kRight;
        config.interface_name = "can0";
        config.address = 0x001;
        config.o6_protocol = O6Protocol::kHopV004; // 若设备当前为 CAN 2.0，改为 kHopV004Can

        HandDevice hand(config);
        hand.open();

        const auto can = hand.get_can_configuration();
        std::cout << "request_id=0x" << std::hex << can.request_id
                  << " response_id=0x" << can.response_id() << std::dec
                  << " mode=" << (can.interface_mode == HopCanInterfaceMode::kCanFd ? "canfd" : "can")
                  << " nominal=" << can.nominal_bitrate
                  << " data=" << can.data_bitrate
                  << " brs=" << can.brs << '\n';

        const auto angles = hand.get_angles(1s);
        for (const auto angle : angles.raw) {
            std::cout << angle << ' ';
        }
        std::cout << '\n';

        hand.close();
    } catch (const std::exception &e) {
        std::cerr << "Error: " << e.what() << '\n';
        return 1;
    }
    return 0;
}
```

> **常见超时排查**：如果运行报 `device request deadline expired`，通常是因为**灵巧手当前模式与代码 `o6_protocol` 不一致**（例如代码写了 `kHopV004`，但设备当前在 CAN 2.0 模式），或者 CAN_H / CAN_L 接反。你可以把 `o6_protocol` 临时换成 `kHopV004Can`（并把 `can0` 配成 `fd off`）重跑一次，看哪一种模式能正常打印 `mode=...` 来确认设备当前状态。

## 切换 HOP 的 CAN 模式

HOP 设备侧的 CAN 帧格式由寄存器 `MI 0x35 / SI 0x06` 控制（`1` = CAN 2.0，`2` = CAN FD），保存到 Flash 由 `MI 0x35 / SI 0x1E = 1` 触发。

切换完整流程固定为三步：**① 查询当前模式 → ② 切换设备侧模式 → ③ 同步修改主机网卡和代码 `o6_protocol`**。

### 第 1 步：查询设备当前模式（只读）

直接运行上一节的完整示例（调用 `hand.get_can_configuration()`），即可打印出设备当前的 `mode=canfd` 或 `mode=can`，以及 `brs` 和速率。不确定设备当前模式时，分别用 `kHopV004`（`fd on`）和 `kHopV004Can`（`fd off`）各试一次即可。

### 第 2 步：切换设备侧模式

> 提示：切到 CAN 2.0 前，设备侧 `brs` 必须为 `0`。`save_to_flash = false`（不写 Flash）时仅临时生效，灵巧手断电重启后会恢复 Flash 中的原配置；建议先临时切换并验证通信正常后，再保存到 Flash。

#### 方式 A：在你的 C++ 程序中调用 `set_can_interface_mode()`（推荐，安装包即可用）

先用设备**当前**模式 `open()`，切换完成后 `close()`，再改用新协议重新打开连接：

```cpp
#include <exception>
#include <iostream>
#include <linkerbot/hand/api/device.hpp>

using namespace linkerbot::hand;

int main() {
    try {
        HandDeviceConfig config;
        config.model = Model::kO6;
        config.side = HandSide::kRight;
        config.interface_name = "can0";
        config.address = 0x001;
        config.o6_protocol = O6Protocol::kHopV004; // 按设备「当前」模式填写：FD 用 kHopV004，CAN 2.0 用 kHopV004Can

        HandDevice hand(config);
        hand.open();

        // 目标模式：HopCanInterfaceMode::kCan20 或 HopCanInterfaceMode::kCanFd
        // 第 2 个参数 save_to_flash：false = 临时生效，true = 写入 Flash
        const auto result = hand.set_can_interface_mode(HopCanInterfaceMode::kCan20, false);
        std::cout << "active_wire_is_fd=" << result.active_wire_is_fd << '\n';

        hand.close();
    } catch (const std::exception &e) {
        std::cerr << "Error: " << e.what() << '\n';
        return 1;
    }
    return 0;
}
```

> **Linux SocketCAN 已知现象（CAN 2.0 → CAN FD）**：当以 `kHopV004Can` 连接并切向 `kCanFd` 时，经典 SocketCAN socket 无法接收切换后立即返回的 FD 确认帧，可能抛出 `CAN FD frame cannot be sent on a classic link`，但**切换指令通常已经发出并生效**。此时不要重复切换，直接按 CAN FD 配置（`fd on` + `kHopV004`）运行上一节的读取程序验证即可；确认已为 `mode=canfd` 后，如需写入 Flash，再在 `kHopV004` 下调用一次 `set_can_interface_mode(HopCanInterfaceMode::kCanFd, true)`。

#### 方式 B：Linux 下用 `cansend` 直接发原始帧（无需写代码）

如果你在 Linux 下已安装 `can-utils`，可以直接发原始 HOP 帧切换（尤其适合从 CAN 2.0 快速切回 CAN FD）。以默认 `request_id = 0x001` 为例（`#` 表示 CAN 2.0 帧，`##0` 表示关闭 BRS 的 CAN FD 帧）：

```bash
# 当前 CAN FD → 切到 CAN 2.0
cansend can0 001##035060101

# 当前 CAN 2.0 → 切到 CAN FD
cansend can0 001#35060102

# 可选：写入 Flash（按切换后的当前格式二选一）
cansend can0 001#351E0101     # 当前为 CAN 2.0 时
cansend can0 001##0351E0101   # 当前为 CAN FD 时
```

#### 方式 C（可选，仅源码构建用户）：SDK 源码自带的 `hop_can_mode` 工具

> 发布安装包不包含 `examples/`，以下仅适用于克隆了 `linkerbot-hand-cpp-sdk` 源码仓库的用户，且必须在 **SDK 源码根目录**执行。

```bash
cmake -S . -B build -DLINKERBOT_BUILD_EXAMPLES=ON
cmake --build build --target hop_can_mode

# 只读查询（默认 CAN FD；查询 CAN 2.0 追加 --from-mode can）
./build/examples/hop_can_mode can0 o6 right --request-id 0x001

# CAN FD → CAN 2.0（如需写入 Flash，追加 --save）
./build/examples/hop_can_mode can0 o6 right --from-mode canfd --mode can

# CAN 2.0 → CAN FD（若报 classic link 提示，直接用上面 FD 只读查询验证）
./build/examples/hop_can_mode can0 o6 right --from-mode can --mode canfd
```

如果退出码为 `2`，表示寄存器已核对但回复仍使用旧帧格式，重启灵巧手后再查询确认。

### 第 3 步：切换后同步主机配置

设备模式生效后，按目标模式同步更新主机 `can0` 和代码中的 `config.o6_protocol`：

| 目标模式 | 主机 `can0` 命令 | 代码配置 |
| --- | --- | --- |
| **CAN 2.0** | `sudo ip link set can0 down && sudo ip link set can0 up type can bitrate 1000000 fd off` | `config.o6_protocol = O6Protocol::kHopV004Can;` |
| **CAN FD** | `sudo ip link set can0 down && sudo ip link set can0 up type can bitrate 1000000 dbitrate 5000000 fd on` | `config.o6_protocol = O6Protocol::kHopV004;` |

## 关节顺序

SDK 按以下顺序读取和设置 6 个关节数据：

| 序号 | 向量下标 | 关节名称 | 说明 |
| ---: | ---: | --- | --- |
| 1 | `0` | `thumb_flex` | 拇指弯曲 |
| 2 | `1` | `thumb_abd` | 拇指侧摆 |
| 3 | `2` | `index` | 食指 |
| 4 | `3` | `middle` | 中指 |
| 5 | `4` | `ring` | 无名指 |
| 6 | `5` | `pinky` | 小指 |

以能力表 `caps.joints[index].name` 为准。

## 身份识别

`get_device_info(1s)` 主动向设备读取并核验身份；`get_identity()` 只返回当前连接缓存的身份信息。

```cpp
const auto info = hand.get_device_info(1s);
std::cout << "序列号: " << info.serial_number.value_or("未知") << '\n';
std::cout << "产品码: " << info.product_code.value_or("未知") << '\n';
```

<a id="capabilities"></a>

## 能力查询

`get_capabilities()` 不发送控制命令，可用于确认当前型号与协议支持的关节范围和功能：

```cpp
const auto caps = hand.get_capabilities();
for (const auto &joint : caps.joints) {
    std::cout << joint.index << ": " << joint.name
              << " raw=" << joint.raw_angle_range.minimum
              << ".." << joint.raw_angle_range.maximum << '\n';
}
```

<a id="angle-control"></a>

## 角度控制

原始角度范围为 `0..255`，百分比范围为 `0..100`（默认与原始值同向）。具体机械姿态与左右手及关节类型相关，不能把侧摆轴的两个端点简单等同于“弯曲/伸直”。

### 角度读取

```cpp
const auto angles = hand.get_angles(1s);
for (const auto raw : angles.raw) {
    std::cout << raw << ' ';
}
std::cout << '\n';
```

`angles.percent` 为逐关节的 `std::optional<double>`，部分配置下可能为空（不可用时不要自行补 `0`）：

```cpp
const auto angles = hand.get_angles(1s);
for (const auto &p : angles.percent) {
    if (p) {
        std::cout << *p << "% ";
    } else {
        std::cout << "N/A ";
    }
}
std::cout << '\n';
```

### 原始角度设置（读 → 设 → 读）

`set_angles()` 接收 6 个 `int32_t`（范围 `0..255`）。下面示例先读当前角度作为目标值（按需修改 `targets[0..5]`），等待命令完成后再回读：

```cpp
const auto before = hand.get_angles(1s);

std::vector<int32_t> targets(before.raw.begin(), before.raw.end());
// targets[5] = 200; // 按需修改安全范围内的目标值，例如小指

const auto cmd = hand.set_angles(targets);
if (!cmd.wait_for(2s)) {
    throw std::runtime_error("set_angles 等待超时");
}
if (const auto err = cmd.error()) {
    std::rethrow_exception(err);
}

// 如需等待手指物理到位后再读，可短暂休眠（需 #include <thread>）
// std::this_thread::sleep_for(500ms);
const auto after = hand.get_angles(1s);
for (const auto raw : after.raw) {
    std::cout << raw << ' ';
}
std::cout << '\n';
```

### 百分比角度设置

`set_percent_angles()` 接收 6 个 `float`（范围 `0..100`），请按实际安全姿态设置目标：

```cpp
std::vector<float> targets(6, 50.0F);
const auto cmd = hand.set_percent_angles(targets);
if (!cmd.wait_for(2s)) {
    throw std::runtime_error("set_percent_angles 等待超时");
}
if (const auto err = cmd.error()) {
    std::rethrow_exception(err);
}
```

<a id="speed-control"></a>

## 速度控制

### 速度设置

原始范围 `0..255`（原始计数，非物理转速）：

```cpp
const auto cmd = hand.set_speeds(std::vector<double>(6, 100.0));
if (!cmd.wait_for(2s)) {
    throw std::runtime_error("set_speeds 等待超时");
}
if (const auto err = cmd.error()) {
    std::rethrow_exception(err);
}
```

### 速度配置读取

```cpp
const auto speeds = hand.get_configured_speeds(1s);
for (const auto v : speeds.raw) {
    std::cout << v << ' ';
}
std::cout << '\n';
```

> 说明：HOP 直接查询设备寄存器；原有 Classic 协议读取本次连接内的写回复缓存（首次读取前需先调用一次 `set_speeds()`）。

<a id="acceleration"></a>

## 加速度设置

### 加速度设置

`set_accelerations()` 接收 6 个原始计数（原有 Classic 为 `0..254`，其中 `0` 表示特殊最大加速度；HOP 为 `0..255`）：

```cpp
const auto cmd = hand.set_accelerations(std::vector<double>(6, 100.0));
if (!cmd.wait_for(2s)) {
    throw std::runtime_error("set_accelerations 等待超时");
}
if (const auto err = cmd.error()) {
    std::rethrow_exception(err);
}
```

### 加速度配置读取

读取的是设备配置的加速度值，而非实时测量加速度：

```cpp
const auto acc = hand.get_configured_accelerations(1s);
for (const auto v : acc.raw) {
    std::cout << v << ' ';
}
std::cout << '\n';
```

<a id="sensor-reading"></a>

## 传感器数据读取

### 电流读取

`get_currents()` 返回实时电流原始计数（区别于电流上限配置，无可靠比例时不要标成 mA）：

```cpp
const auto currents = hand.get_currents(1s);
for (const auto v : currents.raw) {
    std::cout << v << ' ';
}
std::cout << '\n';
```

### 温度读取

原有 Classic 协议单位为摄氏度（°C），HOP 能力表返回原始计数：

```cpp
const auto temps = hand.get_temperatures(1s);
for (const auto v : temps.raw) {
    std::cout << v << ' ';
}
std::cout << '\n';
```

### 触觉点阵读取

使用 `get_force({"fn"}, 1s)` 读取五指法向触觉点阵（Classic 默认 5 指 × 10×4；HOP 按各指传感器描述读取）。缺失手指以 `std::nullopt` 表示：

```cpp
const auto force = hand.get_force(std::vector<std::string>{"fn"}, 1s);
const auto *fn = force.field("fn");
if (!fn) {
    std::cout << "fn: " << force.status("fn") << '\n';
} else {
    for (size_t finger = 0; finger < fn->raw.size(); ++finger) {
        std::cout << "finger " << finger << ": ";
        if (!fn->raw[finger]) {
            std::cout << "无数据\n";
            continue;
        }
        for (const auto value : *fn->raw[finger]) {
            std::cout << value << ' ';
        }
        std::cout << '\n';
    }
}
```

<a id="notes"></a>

## 注意事项与已知限制

- **命令完成语义**：`cmd.wait_for()` 仅表示通信发送或收到设备应答，不代表机械手指已运动到位；等待超时不会取消或自动重发命令。如需严格区分 `kAcknowledged` / `kDispatched` / `kSuperseded` 等终态，见 [API 使用指南](../guides/usage.md)。
- **Classic V1.3.2 速度查询**：不要直接调用底层原生 `speed.get_blocking()`，该请求可能把设备速度改写为 `0`；请使用统一的 `HandDevice::get_configured_speeds()`。
- **HOP 模式切换与适配器边界**：
  - 当前 SDK 的 HOP CAN 2.0 请求未显式标记 Classic 帧，若 `can0` 仍保持 `fd on`，SocketCAN 或 MiniCANFD 可能将其按 FD 帧发送；使用 `kHopV004Can` 时请将 `can0` 设为 `fd off`。
  - `--save` 写入 Flash 后的断电保持效果及更多适配器实测范围见 [O6 HOP 实机记录](../../hardware-acceptance/o6/report.md#o6-hop-2026-11-25)。
- **更多能力与单位说明**：见 [各型号能力说明](../reference/model-capabilities.md)。
