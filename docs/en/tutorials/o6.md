# O6 Feature Guide

O6 has 6 joints. The SDK defaults to the original O6 Classic CAN protocol. Select HOP explicitly on firmware that supports HOP 0.0.4.
This page uses C++ `HandDevice` for common operations. The examples follow the current C++ SDK API.

## Usage

For firmware using the original O6 Classic CAN protocol, configure your environment using [Prepare the communication interface](../connections/prepare-interface.md), then choose [Automatic connection](../connections/automatic.md)
or [Manual connection](../connections/manual.md). The complete read-only Linux SocketCAN program below
provides the `hand` object, chrono literals, and printing/waiting helpers used by the snippets later on this page.
For Windows, replace the device construction code with a verified adapter factory; the feature snippets remain the same.

```cpp
#include <algorithm>
#include <chrono>
#include <cstdint>
#include <exception>
#include <iostream>
#include <stdexcept>
#include <string>
#include <vector>
#include <linkerbot/hand/api/device.hpp>

using namespace linkerbot::hand;
using namespace std::chrono_literals;

template<class Values>
void print_values(const Values &values) {
    for (const auto value : values) {
        std::cout << +value << ' ';
    }
    std::cout << '\n';
}

void check_sample(const SampleMeta &meta) {
    if (!meta.valid) {
        throw std::runtime_error("Sample unavailable");
    }
    if (meta.stale) {
        std::cerr << "Sample is stale; read it again as required by your application\n";
    }
}

void wait_command(const CommandHandle &command) {
    if (!command.wait_for(2s)) {
        throw std::runtime_error("Wait timed out; command was not cancelled and is not automatically resent");
    }
    if (const auto error = command.error()) {
        std::rethrow_exception(error);
    }
    const auto stage = command.stage();
    if (stage != CommandStage::kAcknowledged &&
        !(stage == CommandStage::kDispatched && command.ack_expectation() == AckExpectation::kNone)) {
        throw std::runtime_error("Command did not complete successfully; it may have been replaced or cancelled");
    }
}

void print_sample(const RawVectorSample &sample) {
    check_sample(sample.meta);
    print_values(sample.raw);
}

void print_field(const ForceSample &force, const std::string &name) {
    const auto *field = force.field(name);
    if (!field) {
        std::cout << name << ": " << force.status(name) << '\n';
        return;
    }
    check_sample(field->meta);
    for (size_t finger = 0; finger < field->raw.size(); ++finger) {
        if (!field->raw[finger]) {
            std::cout << "finger " << finger << ": no data\n";
            continue;
        }
        const auto &values = *field->raw[finger];
        for (size_t point = 0; point < values.size(); ++point) {
            if (finger < field->valid_values.size() && field->valid_values[finger] &&
                point < field->valid_values[finger]->size() && !(*field->valid_values[finger])[point]) {
                std::cout << "invalid ";
            } else {
                std::cout << values[point] << ' ';
            }
        }
        std::cout << '\n';
    }
}

int main() try {
    HandDeviceConfig config;
    config.model = Model::kO6;
    config.side = HandSide::kLeft; // Set the actual hand side.
    config.interface_name = "can0"; // This complete program uses Linux SocketCAN.
    HandDevice hand(config);
    std::exception_ptr failure;
    try {
        hand.open();
        // Insert the feature snippet you need here; do not run every control example at once.
        const auto angles = hand.get_angles(1s);
        check_sample(angles.meta);
        print_values(angles.raw);
    } catch (...) {
        failure = std::current_exception();
    }
    try {
        hand.close();
    } catch (const std::exception &error) {
        if (!failure) {
            throw;
        }
        std::cerr << "Failed to close connection: " << error.what() << '\n';
    }
    if (failure) {
        std::rethrow_exception(failure);
    }
    return 0;
} catch (const std::exception &error) {
    std::cerr << error.what() << '\n';
    return 1;
}
```

Place each ordinary C++ snippet below after `hand.open()` succeeds and before `hand.close()`,
keeping these helper functions. The snippets are not standalone programs, and you should not run all control operations at once.
The sections on native Managers provide separate standalone programs.

Unified setters and discrete operations such as `enable()` / `disable()` return a `CommandHandle`.
`wait_command()` waits for termination, then checks the error and final stage: only `kAcknowledged`, or `kDispatched` when no ACK is expected,
counts as completed communication under the corresponding protocol. Replacement, cancellation, and failure are not success; a wait timeout neither cancels nor automatically resends the command.
Your application must separately verify mechanical positioning and control effects.

Check `meta.valid` first, then use `meta.stale` to determine whether a sample has expired; a cached reading is not a live measurement.
If closing fails, a long-running application should retain the same object and schedule cleanup retries rather than immediately opening another connection.

## Manual HOP 0.0.4 connection

HOP defines device registers and messages. CAN 2.0 and CAN FD carry those messages. Set `HandDeviceConfig::o6_protocol` to match the device's **current** protocol and frame format.
This setting selects how the SDK communicates. To change the device's frame format, use the [HOP mode-switching API](#hop-can-mode).

| Setting | Frame format | Addresses |
| --- | --- | --- |
| `O6Protocol::kClassic` (default) | Original O6 Classic CAN | Left `0x28`, right `0x27` |
| `O6Protocol::kHopV004` | HOP 0.0.4, standard CAN FD frames with BRS off on SDK transmissions | Default request ID `0x001`; response ID is the request ID OR `0x400` |
| `O6Protocol::kHopV004Can` | HOP 0.0.4, standard CAN 2.0 frames | Same ID rules as HOP CAN FD |

Connect to HOP devices manually. Specify the actual hand side, request ID, and adapter channel. `open()` reads the device identity and checks the hand side.
Check the CAN_H and CAN_L wiring and bus termination. The tested right hand used `0x001/0x401`, a 1 Mbit/s nominal bitrate, a 5 Mbit/s data bitrate, and BRS off.
For a Linux SocketCAN device with these settings, configure `can0` as follows.

```bash
sudo ip link set can0 down
sudo ip link set can0 up type can bitrate 1000000 dbitrate 5000000 fd on
ip -details link show can0
```

This program reads CAN configuration and angles. For a device already using HOP CAN 2.0, select `kHopV004Can` and configure SocketCAN with the nominal bitrate and `fd off`.

```cpp
#include <exception>
#include <iostream>
#include <linkerbot/hand/api/device.hpp>

int main() try {
    using namespace linkerbot::hand;
    HandDeviceConfig config;
    config.model = Model::kO6;
    config.side = HandSide::kRight;
    config.interface_name = "can0";
    config.address = 0x001;
    config.o6_protocol = O6Protocol::kHopV004;

    HandDevice hand(config);
    hand.open();
    const auto can = hand.get_can_configuration();
    std::cout << "request_id=0x" << std::hex << can.request_id
              << " response_id=0x" << can.response_id() << std::dec
              << " mode=" << (can.interface_mode == HopCanInterfaceMode::kCanFd ? "canfd" : "can")
              << " nominal=" << can.nominal_bitrate << " data=" << can.data_bitrate
              << " brs=" << can.brs << '\n';
    const auto angles = hand.get_angles();
    for (const auto angle : angles.raw) {
        std::cout << angle << ' ';
    }
    std::cout << '\n';
    hand.close();
    return angles.meta.valid ? 0 : 1;
} catch (const std::exception &error) {
    std::cerr << error.what() << '\n';
    return 1;
}
```

## Switching HOP CAN modes

`get_can_configuration()` reads the device's request ID, interface mode, BRS, nominal bitrate, and data bitrate.
Pass `HopCanInterfaceMode::kCan20` or `HopCanInterfaceMode::kCanFd` to `set_can_interface_mode()` to set the device's HOP frame format.
These modes correspond to values `1` and `2` in MI `0x35` / SI `0x06`. Disable device-side BRS before selecting CAN 2.0.
Connect in the device's current mode before switching. Each call sends at most one mode write. Configure the host interface separately.

The Linux SocketCAN example `hop_can_mode` reads identity and CAN configuration by default.

```bash
cmake -S . -B build -DLINKERBOT_BUILD_EXAMPLES=ON
cmake --build build --target hop_can_mode
./build/examples/hop_can_mode can0 o6 right --request-id 0x001
```

- `--from-mode canfd|can` selects the connection's frame format and defaults to `canfd`. `can` applies only to O6 HOP.
- `--mode can|canfd` writes the target mode to volatile configuration by default. Add `--save` to send one Flash save command. Power-cycle persistence remains untested.
- Check the actual reply format using the API result's `active_wire_is_fd`. CLI exit code `2` means the register was verified and replies still use the previous format. Recheck after a controlled restart. Once the new format is active, close the original connection, configure the host interface and adapter for the new mode, and open a new connection with the corresponding `o6_protocol`.
- Switching from CAN 2.0 to CAN FD requires a transport that can receive an immediate FD reply. A Classic SocketCAN connection cannot receive it.
  The current SDK leaves the Classic frame format implicit on HOP CAN 2.0 requests. FD-enabled SocketCAN and MiniCANFD channels can send those requests as FD frames.
  After a timeout, check the device using the target format before attempting another mode write.

The candleLightFD run verified common C++ `HandDevice` operations over HOP CAN FD. The MiniCANFD run verified the C++ FD-to-CAN 2.0 switch and used the vendor API for Classic frame reads and writes and the return to FD.
See the [O6 HOP hardware record](../../hardware-acceptance/o6/report.md#o6-hop-2026-11-25).

## Joint order

The SDK reads and sets joint data in the following order.

| Number | Joint name | Joint |
| ---: | --- | --- |
| 1 | `thumb_flex` | Thumb flexion |
| 2 | `thumb_abd` | Thumb abduction/adduction |
| 3 | `index` | Index finger |
| 4 | `middle` | Middle finger |
| 5 | `ring` | Ring finger |
| 6 | `pinky` | Little finger |

Table numbering starts at 1; C++ vector indices are `0..5`. Use `joints[index].name` in the capabilities as the authoritative name.

<a id="identity"></a>

## Device identity

`get_device_info(1s)` actively reads and verifies device identity. C++ returns a struct; inspect its fields rather than printing the whole object directly.
`get_identity()` only reads the identity cache for the current connection generation.

```cpp
const auto info = hand.get_device_info(1s);
std::cout << "Serial number: " << info.serial_number.value_or("Not reported by device") << '\n';
std::cout << "Product: " << info.product_code.value_or("Not reported by device") << '\n';
```

<a id="capabilities"></a>

## Capabilities

`get_capabilities()` sends no control commands. Use the capabilities to confirm whether the current model/protocol supports an operation,
especially across different firmware, protocols, and sensors for the same model. Joint indices start at 0; table numbering starts at 1.

```cpp
const auto caps = hand.get_capabilities();
std::cout << caps.serialize() << '\n';
for (const auto &joint : caps.joints) {
    std::cout << joint.index << ": " << joint.name << " raw="
              << joint.raw_angle_range.minimum << ".." << joint.raw_angle_range.maximum << '\n';
}
```

<a id="angle-control"></a>

## Angle control

Raw angles range from `0..255`; by default, percentages increase in the same direction as raw values. Determine the mechanical pose from the joint, hand side, and actual angle mapping;
do not simply equate the endpoints of an abduction/adduction or rotation axis with "bent/straight".

### Reading angles

`AngleSample::raw` is a `vector<double>`; `percent` contains an `optional<double>` for each joint.
Do not replace an unavailable percentage conversion with 0.

```cpp
const auto sample = hand.get_angles(1s);
check_sample(sample.meta);
print_values(sample.raw);
for (const auto &percent : sample.percent) {
    if (percent) {
        std::cout << *percent << ' ';
    } else {
        std::cout << "unavailable ";
    }
}
std::cout << '\n';
```

### Setting raw angles

`set_angles()` takes 6 `int32_t` values in joint-table order. This example reads the current values and uses them as targets;
in your application, replace them with confirmed targets within the allowed ranges. Control frames are still sent, so the device may move.

```cpp
const auto sample = hand.get_angles(1s);
check_sample(sample.meta);
std::vector<int32_t> targets(sample.raw.begin(), sample.raw.end());
wait_command(hand.set_angles(targets));
const auto after = hand.get_angles(1s);
check_sample(after.meta);
print_values(after.raw);
```

### Setting percentage angles

`set_percent_angles()` takes 6 `float` values in the range `0..100`. `50.0F` is only the midpoint of each axis mapping;
it is not a universally validated safe pose. Replace it to suit the actual task.

```cpp
std::vector<float> targets(6, 50.0F);
wait_command(hand.set_percent_angles(targets));
```

<a id="speed-control"></a>

## Speed control

### Setting speeds

The raw setting range is `0..255`; it is not a confirmed physical rotational speed.

```cpp
wait_command(hand.set_speeds(std::vector<double>(6, 100.0)));
```

### Reading configured speeds

HOP reads the device register through `get_configured_speeds()`. The original Classic protocol uses the complete speed-write response cached in the current connection, so set the speed first in that connection.
On Classic V1.3.2 firmware, a native `speed.get_blocking()` query may set the device speed to 0.

```cpp
print_sample(hand.get_configured_speeds(1s));
```

<a id="acceleration"></a>

## Acceleration settings

### Setting accelerations

`set_accelerations()` takes 6 raw counts. The original Classic protocol accepts `0..254`. HOP accepts `0..255`.

```cpp
wait_command(hand.set_accelerations(std::vector<double>(6, 100.0)));
```

The original Classic protocol uses `0` to encode special maximum acceleration. The physical conversion for HOP acceleration remains unverified.

### Reading configured accelerations

This reads device configuration, not current measured acceleration.

```cpp
print_sample(hand.get_configured_accelerations(1s));
```

<a id="sensor-reading"></a>

## Reading sensor data

### Reading currents

`get_currents()` reads raw measured-current counts, which differ from current-limit settings. Do not label them as mA without a reliable conversion factor.

```cpp
print_sample(hand.get_currents(1s));
```

### Reading temperatures

The original Classic protocol declares temperatures in degrees Celsius. HOP capabilities report raw counts. Check the sample validity with either protocol.

```cpp
print_sample(hand.get_temperatures(1s));
```

### Reading tactile matrices

Select fields with `get_force(vector<string>{"fn"}, timeout)` and access them through `field("fn")`.
Each optional vector in `raw` corresponds to one finger. `nullopt` means missing data,
and `false` in `valid_values` means an invalid value. The `print_field()` helper above displays this information without filling in zeros or computing sums.

```cpp
const auto force = hand.get_force(std::vector<std::string>{"fn"}, 1s);
print_field(force, "fn");
```

The original Classic protocol defaults to 5 fingers with 10×4 points per finger. HOP reads fields and shapes from each finger's sensor descriptor.

For more features, firmware limitations, and physical units, see [Model capabilities](../reference/model-capabilities.md).
